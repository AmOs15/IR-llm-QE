# report 11-29
LLMを用いたクエリ拡張により、BM25による日本語文書検索タスク（MIRACL-ja）の性能向上を目指す。特に、単純なクエリ生成（Zero-shot）と推論ステップを含めた生成（CoT/AGR）の比較、および元クエリの活用の有無による影響を検証する。

## 実験設定
ベースラインおよび4つの手法を用いて比較検証を行った。

Dataset: MIRACL-ja (dev set, 860 queries)

Metric: Recall@100 (主指標), Recall@10, NDCG@10

LLM: gpt-oss-20b

## 実験したこと
- Baseline<br>
BM25による未処理クエリでの検索<br>
クエリ構成: `Original`
    ```
    experiment-1.json
    ```

- Replacement (Zero-shot)<br>
単純な指示でLLMに生成させ、元クエリと置換<br>
クエリ構成: `Generated`
    ```
    experiment-2.json
    ```

- Replacement (CoT)<br>
AGR手法(Analyze, Generate, Refine)で生成させ、元クエリと置換<br>
クエリ構成: `Generated`
    ```
    experiment-3.json
    ```

- Expansion (Zero-shot)<br>
単純な指示でLLMに生成させ、元クエリに結合<br>
クエリ構成: `Original + Generated`
    ```
    experiment-4.json
    ```

- Expansion (CoT)<br>
AGR手法で生成させ、元クエリに結合<br>
クエリ構成: `Original + Generated`
    ```
    experiment-5.json
    ```

## 考察・分析
1. 「置換」より「拡張（結合）」が有効
- 元クエリを削除してしまうと、検索意図の核が損なわれる可能性が高い
- 元クエリを維持しつつ、LLM生成語で補完するアプローチが必須である
2. CoT（思考連鎖）によるノイズ除去効果
- 単純なZero-shotではBaselineを下回ったが、CoTでは上回った
- Zero-shotでは文脈にそぐわない広義語などの「ノイズ」が含まれやすいが、ステップを踏んで推論させることで、検索に有効な語句のみが選別されていると考えられる
